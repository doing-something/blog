## 1. 배경

[앞서](https://doing-something.github.io/blog/frame-skip-tracking-fixed-vs-adaptive-window/) 영상 속 대상을 따라가는 트래커를 만들고, 처리가 느려 프레임을 건너뛰어도 따라갈 수 있는지 확인했다.
고정 창(지난번 찾은 자리 주변을 본다)은 대상이 한 번에 창 밖까지 움직이자 놓쳤고, 적응형 창(등속운동의 속도로 예상한 자리 주변을 본다)은 좀 더 오래 따라갔다.

트래커는 "몇 초에 어디 있었다"를 기록하는데, 건너뛴 프레임은 기록에 없다. 빠진 기록으로 인해 틀린 결론이 나올 수 있다.

```
6.40초  890
6.70초  876      ← "0.3초 동안 왼쪽으로 14px 갔구나"
```

실제로는 그 사이에 904까지 갔다가 방향을 꺾어 돌아왔다. 기록만으로는 이 반전에 대해 알 수 없다. 간격이 부하에 따라 33ms에서 300ms까지 제멋대로 벌어지는 것도 문제다.  
간격이 고른 표라야 줄 사이의 차이를 바로 비교할 수 있다. 그래서 빠진 줄을 채워 간격이 고른 표를 만들어야 한다.

여기서는 그 채우는 방법인 선형 보간을 정리한다. 먼저 간단한 숫자로 직접 계산해 보고, 그다음 실제 기록에 적용해 오차를 쟀다.

## 2. 선형 보간

알고 있는 두 값을 직선으로 이어서, 그 사이의 값을 추측하는 방법이다. 어떤 물체의 위치를 두 번 측정했다고 하자.

- 0초: x = 10
- 1초: x = 20

0초와 1초 사이에는 측정값이 없다. 하지만 물체가 두 위치 사이를 일정하게 움직였다고 가정하면 0.5초의 위치를 추측할 수 있다: 직선의 한가운데인 15다.

시작 값을 a, 끝 값을 b, 진행 비율을 t(0\~1, 단위 없음)라고 하면:

```
보간 결과 = a + (b - a) × t
```

```js
function lerp(a, b, t) {
  return a + (b - a) * t;
}
```

lerp는 linear interpolation의 줄임말이다.

실제 데이터에서는 시간이 0초, 1초로 깔끔하게 나오지 않는다. 그래서 알고 싶은 시간이 두 기록 사이의 어디쯤인지를 계산해서 t로 쓴다.

```
t = (알고 싶은 시간 - 시작 시간) ÷ (끝 시간 - 시작 시간)

예상 위치 = 시작 위치 + (끝 위치 - 시작 위치) × t
```

```js
function interpolatePosition(
  startTime,
  startPosition,
  endTime,
  endPosition,
  targetTime,
) {
  const t = (targetTime - startTime) / (endTime - startTime);
  return startPosition + (endPosition - startPosition) * t;
}
```

## 3. 리샘플링

보간을 쓰면 간격이 고르지 않은 기록을 간격이 고른 표로 다시 만들 수 있다. 이를 리샘플링(resampling)이라고 한다.

```
원본 측정 시간:    0ms, 33ms, 68ms, 101ms
새로 만들 시간표:   0ms, 50ms, 100ms
```

원본에는 정확히 50ms인 값이 없다. 50ms를 사이에 둔 두 측정(33ms, 68ms)으로 보간한다.

```
33ms ───────── 50ms ───────── 68ms
x=10           x=?            x=20

t = (50 - 33) / (68 - 33) = 17 / 35 ≈ 0.486
x = 10 + (20 - 10) × 0.486 ≈ 14.86
```

이렇게 새 시간표의 모든 칸을 채우면 간격이 고른 표가 나온다.

## 4. 보간과 외삽의 차이

보간은 이미 알고 있는 두 점 사이를 구한다. 외삽(extrapolation)은 알고 있는 점 바깥쪽을 추측한다.

```
보간:    알고 있음 ──── ? ──── 알고 있음
외삽:    알고 있음 ──── 알고 있음 ──── ?  (미래)
```

앞 글의 트래커는 직전 속도로 다음 위치를 미리 예측했다. 아직 오지 않은 위치를 구했으니 보간이 아니라 외삽이다.

보간은 두 값 사이를 일정한 빠르기로 곧게 움직였다고 가정하고 그 사이를 채운다. 실제로 그렇게 움직였다면 채운 값도 맞다. 그 사이에 방향을 바꾸거나 속도가 달라졌다면 채운 값은 틀린다. 다만 틀려도 채워 넣은 줄만 틀리고, 실제로 측정한 줄은 그대로다.

외삽은 예측이 맞았는지 확인할 실제 값이 없다. 앞 글에서 예측이 틀리자 창을 엉뚱한 자리에 두었고, 대상을 놓쳤다.

## 5. 가정이 맞을 때와 깨질 때

"두 값 사이를 일정한 빠르기로 곧게 움직였다"는 가정이 맞을 때와 깨질 때를 간단한 숫자로 계산해 봤다.

**가정이 맞는 경우.** 트래커 기록이 두 줄뿐이다.

```
2.005초  x=320
2.305초  x=362
```

t = (2.105 − 2.005) ÷ (2.305 − 2.005) ≈ 0.333으로 2.105초를 보간하면 320 + 42 × 0.333 = 334다. 이 영상의 실제 움직임은 등속 140px/s이고, 실제 위치도 334다. 오차가 0이다. 두 기록 사이를 직선으로 움직였다는 가정이 실제와 같기 때문이다.

**가정이 깨지는 경우.** 대상이 두 기록 사이에서 방향을 꺾으면 어떻게 되는지 계산해 보자.

```
6.40초  x=890   (기록됨)
6.50초  x=904   (실제 위치. 화면 끝에서 반전, 기록 없음)
6.70초  x=876   (기록됨)
```

기록된 두 줄로 6.50초를 보간하면 890 + (876 − 890) × 0.333 ≈ 885.3이다. 실제는 904, 오차는 18.7px이다. 직선을 벗어난 움직임이 빠진 구간 안에 있으면, 보간은 그 사실을 알 수 없고 오차로 남는다.

그래도 프레임 간격이 짧고 움직임이 급격하지 않다면, 계산이 단순하면서 꽤 쓸 만한 근사값을 얻는다.

## 6. 실험: 줄을 지우고 다시 채워서 채점

앞 장의 계산을 실제 기록으로 확인했다. 앞 글의 트래커가 부하 0에서 15초 동안 남긴 기록(448줄, 33ms 간격, 놓친 줄 0)에서 일부러 줄을 지워 빠진 구간을 만들고, 남은 줄로 보간해서 지운 자리를 채운 뒤, 지우기 전의 원래 값과의 거리(px)를 쟀다. 지운 값이 곧 정답이라 채점이 그대로 된다. 빠진 구간은 세 가지 크기로 만들었고(3·9·15줄 ≈ 130·330·530ms), 구간마다 그 안의 원래 움직임이 등속이었는지 반전을 품었는지로 나눠 집계했다.

| 빠진 구간 크기  | 등속: 평균 / 최대 오차 | 반전 포함: 최대 오차 |
| --------------- | ---------------------- | -------------------- |
| 3줄 (약 130ms)  | 0.72 / 4.04px          | 6.86px               |
| 9줄 (약 330ms)  | 0.73 / 2.25px          | 22.00px              |
| 15줄 (약 530ms) | 0.72 / 2.45px          | 36.27px              |

결과는 계산에서 예상한 대로 갈렸다.

- **등속 구간의 오차는 구간 크기와 상관없다.** 평균 0.72px로 세 크기가 같다. 이 크기는 보간의 오차가 아니라 트래커 기록 자체의 흔들림이다(앞 글에서 부하 0일 때 1\~2px). 2px을 넘은 줄은 전부 원인이 따로 있었다: 기록 시작 직후 0.15초(트래커가 막 따라가기 시작해 기록 자체가 흔들리는 구간)와, 방향을 꺾은 지점이 남은 줄 바로 옆이어서 등속으로 잘못 분류된 구간 하나. 이 둘을 빼면 최대 오차는 1.63\~1.78px로, 세 크기 모두 기록 흔들림 범위 안이다.
- **반전을 품은 구간의 오차는 구간 길이에 비례해 커진다.** 6.86 → 22.00 → 36.27px. 크기도 계산과 맞는다: 반전 지점의 오차는 "속도 × 방향을 꺾은 지점에서 가장 가까운 남은 줄까지의 시간"만큼 나는데, 예를 들어 9줄 구간의 실측 22.0px에 대해 이 계산은 22.8px을 준다. 5장에서 본 그 오차가 실제 기록에서 그대로 재현된 것이다.

## 7. 정리

- 빠진 구간은 선형 보간으로 채울 수 있다. 움직임이 일정한 구간이라면, 구간이 길어도 채운 값의 오차는 기록 자체의 흔들림 수준(0.7px)에 머문다.
- 대상이 구간 안에서 방향을 꺾었다면 채운 값은 틀린다. 이 오차는 구간이 길수록 커지고, "속도 × 방향을 꺾은 지점에서 가장 가까운 남은 줄까지의 시간"으로 미리 어림할 수 있다.
- 보간은 이미 있는 줄을 바꾸지 않는다. 그래서 틀려도 채운 자리만 틀린다.
- 기록이 시작된 직후는 트래커가 자리를 잡기 전이라 기록 자체가 크게 흔들린다. 이 구간은 채우는 재료로도, 채점 기준으로도 쓰지 않는다.

## 8. 한계

- 일정한 속도로 왕복하는 합성 영상 하나, Chrome 한 조합에서만 측정했다.
- 방향을 꺾는 지점이 두 곳뿐이었다. 그중 한 곳은 화면 끝에 눌려서 오차가 작게 나오는 자리였다.
- 줄을 규칙적으로 지워서 빠진 구간을 만들었다. 실제 부하에서는 간격이 불규칙하게 벌어지므로 완전히 같은 상황은 아니다.
- 구간을 등속과 반전으로 나누는 판정이 완벽하지 않다. 방향을 꺾은 지점이 남은 줄 바로 옆이면 반전 구간이 등속으로 집계된다. 실험에서 실제로 한 번 있었다.
